# 全市场 T+1 执行链路与影子价格带设计

日期：2026-09-03
状态：已批准，待实施计划
方案：A（正式价格下限 50 元，40–49.99 元仅影子评估）

## 1. 背景与问题

当前生产流程由两个未闭合的部分组成：

- `fast_t1_scan.py` 从完整 A 股市场生成动态候选并计算机会分，但不生成独立执行分、连续分钟确认、`buyable` 或状态机结果。
- `local_workflow.py` 默认命令负责客观数据采集；已有 V2 双轴与状态机仅通过固定 `watchlist.json` 构建，不能直接消费全市场动态候选。

因此，13:45 任务即使获得完整静态快照和大部分分钟数据，也无法形成满足冻结合同的可审计执行结论。2026-09-03 的数据还暴露了两个质量问题：分钟采集实际覆盖 171 分钟，但输出审计中的 `actual_minutes` 为 1；全市场行业映射覆盖 92.99% 时，整体结果被降为 `partial`，即使某个候选自身的行业证据完整也无法继续执行评估。

本设计修复生产闭环，不通过降低机会分或执行分门槛制造候选。

## 2. 目标

1. 从完整市场动态生成候选，并保留覆盖、漏斗和入池原因。
2. 对动态候选计算独立机会分与执行分，运行连续分钟、VWAP、活动度、买区、禁追、风险收益和可执行性门禁。
3. 输出互斥的可执行候选、条件观察和明确不买，并且只有 `buyable=true` 能进入 `only_choose_one`。
4. 正式候选价格下限保持 50 元；40–49.99 元进入影子评估，但永不产生生产买入资格。
5. 将市场级数据质量和候选级数据质量分离，避免无关股票的数据缺失否决数据完整的候选。
6. 修复分钟审计口径，使质量状态反映本轮实际分钟采集。
7. 生成新的冻结总规则版本，保留原版本并更新四轮自动化引用。

## 3. 非目标

- 不修改正式机会分或执行分阈值。
- 不放开创业板、科创板或北交所权限限制。
- 不自动下单，不连接券商账户。
- 不把影子候选计入正式候选、条件观察或 `only_choose_one`。
- 不重写现有生命周期引擎；只增加全市场动态候选适配层。

## 4. 架构

### 4.1 动态候选联合

从 `fast_t1_scan.py` 抽出可复用的候选生成结果，并写出版本化候选联合文件。每条记录至少包含：

- 代码、名称、市场、板块、行业；
- 快照价格和时间；
- 进入候选池的原因；
- 机会分及其加减分明细；
- 日线趋势、量比、流动性和风险标签；
- 建议买区、禁追线、保护位和风险收益预估；
- `price_band`：`production`、`shadow_40_50` 或 `excluded`。

动态候选联合只能来自本轮完整市场扫描，不允许由固定自选池替代。

### 4.2 全市场执行评估器

新增独立模块消费：

- 动态候选联合；
- `latest_codex_input.json` 指向的本轮快照、日线、行业和分钟文件；
- 市场宽度及质量审计。

评估器按代码联接客观数据，并为每只候选输出：

- `opportunity_score` 与 `execution_score`；
- 策略通道；
- 全日 VWAP、午后锚定 VWAP、命名关键位；
- 连续站稳分钟数、活动度是否收缩；
- 买区、确认位、禁追线、执行保护位和隔夜风险位；
- 风险收益、一手资金占用和费后经济性；
- `candidate_data_status`、`decision`、`buyable` 和标准化原因码；
- `production_buyable`。

评估结果必须使用现有生命周期模块的双轴决策和状态机语义，适配层只负责准备输入和补充生产门禁，不复制另一套状态机。

### 4.3 决策输出

新增版本化的全市场决策 JSON，包含：

- 数据版本、策略版本、规则版本和输入文件校验信息；
- 完整市场覆盖和筛选漏斗；
- 市场环境；
- 可执行候选、条件观察、明确不买和影子观察；
- `only_choose_one`；
- 每个候选的完整门禁证据和原因码。

生产组规则：现价至少 50 元，且所有门禁通过。影子组规则：现价为 40–49.99 元，完整运行同一评估器，但强制：

```text
production_buyable = false
buyable = false
only_choose_one_eligible = false
```

影子结果单独落入审计账本，用于累计至少 3 个交易日、每通道至少 20 个可评分样本后的后续治理。

## 5. 数据质量设计

### 5.1 两层质量状态

市场级质量用于判断是否能描述全市场环境；候选级质量用于判断某只股票能否进入执行评估。

- 市场级行业映射低于目标覆盖率时记录降级提示，但只要全市场快照、宽度和主要行业聚合仍可用，不直接否决所有候选。
- 候选自身缺行业、分钟、VWAP、日线或可执行性字段时，该候选返回 `data_insufficient`。
- 市场快照覆盖异常、交易日不符或关键价格字段普遍缺失时，仍保持全局 `data_not_ready`。

### 5.2 分钟审计

质量判定使用本轮 `intraday_minutes.parquet` 的去重交易分钟数和动态期望分钟数，不使用向共享缓存追加的单次快照数量代替完整分钟覆盖。

输出同时保留：

- 本轮采集分钟数；
- 本轮具有分钟数据的股票数；
- 可计算 VWAP 的股票数；
- 缺失分钟、连续性断点和覆盖率；
- 候选逐只分钟证据状态。

共享缓存只能用于历史留存，不能提升本轮候选的数据质量。

## 6. 编排与命令

为 `local_workflow.py` 增加一个面向全市场生产决策的明确子命令。该命令依次：

1. 校验本轮 `latest_codex_input.json`；
2. 生成或读取同一轮次的动态候选联合；
3. 运行全市场执行评估器；
4. 写出版本化决策 JSON 和审计账本；
5. 返回非零退出码处理不可恢复的数据合同错误。

四轮自动化仍按各自职责运行，但共同引用新版冻结总规则。13:45 和 14:40 使用完整执行评估；11:30 在连续分钟证据不足时只允许条件观察；09:45 只使用可追溯历史决策进行复盘。

## 7. 错误处理

- 候选联合与正式交接时间不属于同一交易日或相差超出允许窗口：全局 `data_not_ready`。
- 某候选联接不到行业或分钟数据：仅该候选 `data_insufficient`。
- 分钟采集覆盖不足：禁止连续确认；允许静态研究结果，但不能 `buyable=true`。
- 影子候选无论评分多高都不能进入生产决策。
- 任何输入缺失都输出明确原因码，不做自然语言补值。
- 写入决策文件使用临时文件加原子替换，避免半写文件被自动化读取。

## 8. 测试策略

实施采用测试先行，至少覆盖：

1. 全市场候选联合不是固定自选池，且保留扫描覆盖与入池原因。
2. 50 元边界进入生产价格带；40 元和 49.99 元进入影子带；低于 40 元排除。
3. 影子候选即使双轴通过也始终不能 `buyable` 或进入 `only_choose_one`。
4. 候选有完整行业证据时，不因无关股票行业缺失被否决。
5. 候选缺行业、分钟或 VWAP 时逐只返回 `data_insufficient`。
6. 分钟审计使用本轮完整分钟文件，能复现并修复“171 分钟被记录为 1 分钟”。
7. 单次快照不能通过连续分钟门禁。
8. 只有机会分、执行分和全部硬门禁同时通过时，才允许 `buyable=true`。
9. `only_choose_one` 只从生产可买候选中产生；全部失败时为 `null`。
10. 旧版固定自选池路径继续通过现有测试，防止无关回归。

验收命令包括目标测试、完整测试集以及使用已保存 2026-09-03 运行数据的离线回放。离线回放预期能够给出完整、可审计的“无可执行候选”，而不是因缺少执行层返回无法判定。

## 9. 版本与发布

- 原冻结总规则文件保持不变。
- 创建新的冻结总规则文件，写明新命令、两层数据质量、影子价格带和审计要求。
- 先完成代码与离线验收，再更新四个自动化任务引用；不得让自动化提前指向未通过验证的新规则。
- 回滚时恢复四个自动化对旧规则的引用即可，历史决策和影子账本不删除。

## 10. 成功标准

- 同一轮完整市场数据可生成带双轴评分和门禁证据的动态全市场决策文件。
- 数据完整但无标的通过时，输出“全市场无合规新开仓标的”，不再误报 `data_not_ready`。
- 数据确实缺失时，能够区分全局不可用与个股不可用。
- 40–49.99 元候选只产生可审计影子结果，不影响正式交易结论。
- 四轮自动化均引用同一新版冻结规则，且旧版可回滚。
