# AlphaSift 客观数据管线设计

## 目标

将 AlphaSift 本地运行端重构为客观市场数据服务。本地项目只负责采集、校验、缓存和返回数据；Codex 负责动态候选并集、指标解释、排序、拒绝、交易计划、概率估计和最终标的选择。

## 职责边界

本地运行端负责：

- 采集全市场实时价格、成交量、成交额、换手率和量比。
- 保存最近 250 个交易日的原始日线。
- 按明确请求保存当前交易日的原始分钟线。
- 计算中性的数学指标：VWAP、MA、RSI、MACD 和 ATR。
- 保存行业、概念和产业链基础映射。
- 校验行数、时间、覆盖率、重复代码和接口错误。
- 根据 Codex 明确指定的股票代码机械补取数据。

本地运行端不得：

- 建立候选池或选择固定前 N 只股票。
- 解释行业、题材、指标或事件的好坏。
- 排名、筛选、拒绝、推荐或执行遗漏分析。
- 输出买入区、禁追价、止损、卖区、概率或最终标的。
- 输出策略分、信号分、推荐标签，或在日志中使用策略结论措辞。

## 运行入口

### 全市场采集

```powershell
python local_workflow.py
```

这是唯一需要用户启动的操作。程序刷新全市场客观数据，更新全量日线缓存，计算中性指标，更新基础分类映射，写入审计结果，并发布最新数据交接入口。

### 响应 Codex 数据请求

```powershell
python local_workflow.py fulfill-request
```

Codex 写入 `codex_data_request.json` 后直接调用该命令，用户不需要选择或粘贴股票代码。程序读取明确代码，补取请求的当前交易日分钟数据和日线字段，然后写入 `codex_data_response.json`，全程不筛选、不排序、不解释。

## 目标模块结构

```text
local_workflow.py
alphasift/

```

已经验证稳定的数据源、标准化、超时、重试和缓存代码应继续复用。本地运行链路移除策略编排和策略输出。确认不存在导入依赖后，删除不再承担数据职责的策略模块、命令、测试、YAML 和文档。

## 全市场数据流程

1. 获取沪深市场实时快照。
2. 获取全市场参考快照；必要时使用现有腾讯备用链路刷新北交所行情。
3. 标准化股票代码和客观行情字段。
4. 拒绝过期快照、重复代码、无效价格、市场覆盖不完整或行数异常骤降的数据。
5. 保存标准化后的原始全市场快照。
6. 通过可恢复批处理，为每个有效股票代码获取最近 250 个交易日日线。
7. 先保存原始日线，再计算数学指标。
8. 计算中性指标，不生成分类、评分或方向判断。
9. 更新行业、概念和产业链基础映射。
10. 写入审计、清单、进度日志和最新数据入口。

## 日线备用接口链

日线历史数据使用现有多源链路：

1. 配置 Token 时优先使用 Tushare。
2. 腾讯直连日线接口。
3. 新浪直连日线接口。
4. AkShare。
5. Baostock。

每个数据源独立配置限速、重试、超时、健康状态和临时熔断。发生成功降级时，记录请求源、实际源、前序错误、抓取时间、最新交易日和数据行数。原始数据按股票代码及复权口径缓存。

全量 5528 只股票的日线刷新支持断点续跑。断点文件记录已完成、失败和待处理代码。程序重启后跳过当日有效缓存，只重试尚未完成的代码。某个接口失败不得删除或覆盖已成功保存的数据。

## 中性数学指标

指标层只允许输出数值和计算元数据：

- `ma5`、`ma10`、`ma20`、`ma60`、`ma120`、`ma250`
- `rsi14`
- MACD 的 DIF、DEA 和柱值
- ATR14 和 ATR 百分比
- 请求分钟数据的当日 VWAP
- 输入行数、首个日期、最后日期和计算时间

指标层不得输出多头、空头、改善、恶化、信号分、质量排名、突破判断、候选状态或推荐文本。

## Codex 请求协议

请求文件：`data/daily_runs/codex_data_request.json`

```json
{
  "schema_version": 1,
  "request_id": "20260722-001",
  "codes": ["600519", "002190"],
  "daily": {
    "lookback": 250,
    "fields": ["raw", "ma", "rsi", "macd", "atr"]
  },
  "minute": {
    "date": "2026-07-22",
    "start": "09:30",
    "end": "13:40",
    "fields": ["raw", "vwap"]
  }
}
```

校验规则：

- 股票代码必须是唯一的六位 A 股代码。
- 分钟请求只允许当前交易日。
- 开始时间不得晚于结束时间。
- 字段必须属于明确的客观数据白名单。
- 未知字段、错误日期或无效代码必须在调用接口前拒绝。

响应文件：`data/daily_runs/codex_data_response.json`

响应包含相同的 `request_id`、抓取时间、逐代码数据、来源元数据、覆盖率和逐代码错误，不包含排名、策略或推荐字段。响应文件采用原子写入，防止 Codex 读取到未完成内容。

## 输出协议

每次全量运行建立时间戳目录，包含：

- `market_snapshot.csv`
- `market_snapshot.json`
- `daily_indicators.csv`
- `classification_map.csv`
- `data_audit.json`
- `manifest.json`
- `workflow.log`

原始日线保存在可复用的逐代码缓存中，不在每个运行目录重复复制。最新交接 JSON 指向本次运行文件并记录缓存覆盖率。删除现有 `local_reference_score`、`local_reference_rank`、本地信号分、固定候选文件和推荐输出。

## 进度与日志

终端和 `workflow.log` 只使用数据采集措辞，显示：

- 阶段开始时间、当前时间和累计耗时。
- 全市场已完成、缓存命中、失败和待处理数量。
- 当前处理速度和预计剩余时间。
- 各接口成功、降级、重试、限速和熔断次数。
- 慢请求或失败请求的股票代码及单次耗时。
- 断点文件路径和最后完成代码。
- 最终覆盖率和错误汇总。

运行日志不得出现候选、推荐、买入、卖出、禁追、概率或最终选择等策略结论。

## 数据审计规则

审计模块独立校验：

- 总行数和沪、深、北各市场行数。
- 唯一代码数和重复行。
- 快照生成时间和行情时间范围。
- 必需实时行情字段覆盖率。
- 当前全市场范围内的日线缓存覆盖率。
- 上市历史允许时是否具有 250 条日线；历史不足时记录原因。
- 最新日线日期分布。
- 中性指标覆盖率和计算错误。
- 行业、概念和产业链基础映射覆盖率。
- 请求分钟数据的覆盖率和时间区间边界。
- 接口错误、重试、降级和过期缓存使用情况。

所有缺失数据必须明确报告。停牌、新股历史不足、无可比基准导致量比不可用等情况应归类为客观状态，不得静默填充。

1. 为客观请求、审计、指标和采集流程编写测试。

5. 从本地入口删除预筛和午后终筛命令。

## 验收标准

- 用户启动一次即可完成客观全市场采集，本地不建立候选池。
- 日线缓存尝试覆盖当日全市场全部代码；中断恢复后不得重复抓取有效的当日缓存。
- 所有本地指标只能是数值或计算元数据，不得包含方向解释。
- 默认输出不得包含本地排名、参考分、信号分或策略结论字段。
- 合法 Codex 请求只能为指定代码和当前交易日分钟区间生成原子响应。
- 非法请求必须在调用数据接口前失败，并返回可执行的校验错误。
- 日志必须显示时间、进度、速度、预计剩余时间、覆盖率和接口错误，且使用中性数据措辞。
- 自动化测试必须覆盖请求校验、数据源降级、断点恢复、中性指标计算、输出协议和策略字段禁用检查。
